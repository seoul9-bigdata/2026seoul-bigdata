## 01 `01_medical_access.py` → outputs 01~04

### 핵심 로직

```
동 centroid → 반경 내 시설 수 카운트
  일반인: 1.28 m/s × 1800s × tobler(slope) → 동별 가변 반경
  노인:   0.88 m/s × 1800s × tobler(slope) → 동별 가변 반경
  손실률 = (1 - 노인 도달수 / 일반인 도달수) × 100
```

**경사 보정 (Tobler's Hiking Function):**

```
표고점(N3P_F002.shp) → 행정동 공간결합 → 동별 h_range = h_max - h_min
slope_est = h_range / (√동면적 × 1.13)   ← 원형 동 가정, 지름 근사
V(s) = 6 × exp(-3.5 × |s + 0.05|)        ← Tobler 함수 (km/h)
ratio = V(slope_est) / V(0)               ← 0 < ratio ≤ 1
일반인 반경 = 2304m × ratio
노인 반경   = 1584m × ratio               ← 동일한 ratio 적용
```

**설계 이유**

일반인과 노인 모두에게 같은 경사 패널티 비율을 적용합니다. 같은 비율을 곱하면 경사 효과가 분자·분모에서 상쇄되어, 손실률은 순수하게 **속도 차이(0.88 vs 1.28 m/s)에서 오는 접근성 격차**만 반영합니다. 노인에게만 경사를 적용하면 실제보다 손실이 과장되어 데이터 왜곡이 발생합니다.

검증: 이론적 손실률 `1 - (0.88/1.28)² ≈ 52.7%` vs 실측 **51.7%** — 두 값이 근접하면 모델이 정상 동작하고 있다는 뜻입니다.

## 03 `03_trip_chaining.py` → outputs 08~09

### 핵심 로직

```
각 동 centroid(집)에서 scipy.spatial.cKDTree로:
  d1: 집 → 가장 가까운 병원
  d2: 그 병원 → 가장 가까운 약국
  d3: 그 약국 → 집 (귀가)
  총 동선 = d1 + d2 + d3

총 동선 > 1,584m  →  "30분 내 원스톱 불가"
병원 200m 이내 약국 존재  →  "원스톱 클러스터"
```

**설계 이유**

처방전을 들고 약국까지 이동해야 하는 삼각 동선 전체가 노인의 30분 한계(1,584m) 안에 들어오는지 확인합니다. cKDTree로 426개 동 × 수만 개 시설 최근접 쿼리를 O(log n)으로 처리합니다.

**결과**

| 지표 | 값 |
|------|-----|
| 30분 내 원스톱 불가 동 | **21개 (4.9%)** |
| 삼각 동선 평균 총 거리 | **576m** |
| 원스톱 클러스터 30분 내 접근 가능 동 | **424개 (99.5%)** |

### `08_trip_chain_map.html`

동별 삼각 동선 총 거리 코로플레스. 30분 초과 동 빨간 외곽선 강조.

### 핵심 로직

**Python — 사전 계산**

```python
# Tobler CSV 병합
tr_df = pd.read_csv("outputs/tobler_ratio_LEE.csv", dtype={"dong_code": str})
gdf_dong = gdf_dong.merge(tr_df[["dong_code","tobler_ratio"]], ...)
gdf_dong["t_ratio"] = gdf_dong["tobler_ratio"].fillna(1.0)

tr_flat  = np.ones(len(gdf_dong))       # 경사X: 보정 없음
tr_slope = gdf_dong["t_ratio"].values   # 경사O: Tobler 비율 적용

# COUNTS 48키 생성
COUNTS = {}
for sp in SPEEDS:                         # young/snr0/snr1/snr2
    for tmin in [15, 30, 45]:
        for slope_key, tr in [("flat", tr_flat), ("slope", tr_slope)]:
            r = sp["speed"] * tmin * 60 * tr      # 동별 보행 반경 [426]
            nh  = (DH <= r[:, None]).sum(axis=1)  # 병원 도달 수 [426]
            np_ = (DP <= r[:, None]).sum(axis=1)  # 약국 도달 수 [426]
            for ftype, cnt in [("hosp", nh), ("pharm", np_)]:
                key = f"{sp['id']}_{tmin}_{ftype}_{slope_key}"
                COUNTS[key] = {dc: int(cnt[i]) for i, dc in enumerate(dong_codes)}
```

**JavaScript — 동적 점수 계산**

```js
// A는 항상 일반인(young), B는 선택된 노인 속도
function getN(speedId, time, ftype, dc, isSlope) {
  const s = isSlope ? 'slope' : 'flat';
  if (ftype === 'all')
    return (COUNTS[speedId+'_'+time+'_hosp_'+s][dc] || 0)
         + (COUNTS[speedId+'_'+time+'_pharm_'+s][dc] || 0);
  return COUNTS[speedId+'_'+time+'_'+ftype+'_'+s][dc] || 0;
}

function dongScore(dc) {
  const nYoung = getN('young', cT, cF, dc, cSlope);  // 일반인 분모
  const nB     = getN(SPEEDS[cB].id, cT, cF, dc, cSlope);
  return nYoung > 0 ? (nB / nYoung) * 100 : 100;
}
```

**설계 이유**

- 도달가능 점수는 "일반인 대비 노인이 얼마나 접근 가능한가"를 직관적으로 전달. 100점 = 동등, 50점 = 절반만 가능.
- A를 일반인으로 고정하면 일관된 비교 기준이 유지되고, 팀 conclusion.html의 점수 체계와 통일됩니다.
- `_flat`/`_slope` suffix로 캐시를 재사용하면서 경사 시나리오 두 가지를 동시에 보존합니다.
- 경사 보정 시 일부 구(관악·금천)는 오히려 점수가 올라가는데, 이는 고지대 특성상 일반인 반경도 함께 줄어들어 분모가 감소하기 때문입니다.
